# omp-qq-bridge

项目内的 **OneBot 11 正向 WebSocket ↔ omp** 桥接。当前测试预发布版为 **4.1.0-beta.1**，源码与反馈见 [GitHub 仓库](https://github.com/gulanthys/omp-qq-bridge)。自动接收当前 QQ 账号上报的所有私聊和群聊消息；新聊天首次发消息时自动建立上下文，**不需要配置 QQ 号、群号或会话 ID**。

OneBot、卡片及转发解析参考 [Yuuyuko-uu/dsh-qq-bridge](https://github.com/Yuuyuko-uu/dsh-qq-bridge)，保留上游作者署名与 [MIT LICENSE](LICENSE)。不修改参考仓库，不安装到 DSH，不提供 Web 管理页面。

## 启动与初始化

前置条件：Node.js 24+、PATH 中的原生 `omp` 和可用的 OneBot 11 后端。启动示例使用 Windows PowerShell；macOS 可将路径分隔符改为 `/`。当前验证基线为 **omp 18.18.0**，此前也在 18.16.0 运行过；其他版本及认证方式不作兼容保证。**不要求安装 OMP Echo Memory 或任何记忆插件**。

先在 NapCat 等 OneBot 后端开启**正向 WebSocket 服务**，使用同时支持 API 和事件的地址，例如 `ws://127.0.0.1:3001/`。端口以你的后端配置为准，不是原来的 HTTP 地址。标准 OneBot `/api` 只提供 API、`/event` 只提供事件，需要使用两者合一的 `/` 端点或等价代理地址。建议使用消息段数组上报；CQ 字符串可作为文本进入上下文，但不等于已解析其中的媒体。

在你选定的项目根目录执行（将独立仓库克隆为该项目的子目录）：

```powershell
git clone --branch v4.1.0-beta.1 https://github.com/gulanthys/omp-qq-bridge.git omp-qq-bridge
node .\omp-qq-bridge\launch.mjs
```

启动器默认只加载 QQ 扩展；主会话、模型配置、QQ 收件箱和聊天上下文均使用本目录的 `.runtime/`。不导入 OMP Echo Memory 的启动器或内部源码，不全局安装、不修改全局插件设置，也不复制全局登录或其他项目记忆。

在本机主会话选好并验证模型，然后运行：

```text
/omp-qq-bridge /init
```

只填写 **WebSocket 地址、Access Token**，然后确认是否启用；仅在发现记忆提供者时额外确认共享范围。之后任何新私聊或新群消息都会自动接入，不需要再次添加联系人。地址留空采用显示的默认值，Token 留空表示不用 Token；取消弹窗不会保存半份配置。

普通运行不需要安装 npm 依赖；WebSocket 客户端使用运行时内置实现。启动器支持 `--model`、`--thinking`、`--mode`、`--no-ui` 和项目内扩展 `-e` / `--extension`，例如：

```powershell
node .\omp-qq-bridge\launch.mjs --model provider/model-id
```

QQ 子会话使用启用时选定的模型。切换主会话模型后，停止、重新启用桥接以更新。每轮重新解析模型认证，解析出的模型 Key 和请求头只通过子进程环境传递，不写入桥接模型配置或命令行。进程内自定义 API 无法直接序列化，明确拒绝，不自动替换模型；其他内置协议及特殊 OAuth/云认证仍需实际账号验证。

## 独立与组合

可选配套版本是 [OMP Echo Memory 1.1.0-beta.1](https://github.com/gulanthys/omp-echo-memory)。两者是独立仓库，不需要共同父仓库；组合运行时将两者放在同一个项目根目录下。先显式创建本项目的记忆绑定及通用人格模板，再按需编辑本地 `omp-echo-memory/persona.json`：

```powershell
git clone --branch v1.1.0-beta.1 https://github.com/gulanthys/omp-echo-memory.git omp-echo-memory
node .\omp-echo-memory\cli.mjs init
```

公开仓库不提供使用中的人格、项目绑定或记忆数据。初始化不调用模型，不会覆盖有效的本地配置或把复制来的其他项目数据重新绑定；已有安装的迁移与边界见 [OMP Echo Memory 文档](https://github.com/gulanthys/omp-echo-memory)。

两个启动器都只默认加载自己，通过显式 `-e` 组合，不根据目录是否存在自动安装或加载：

```powershell
# QQ 单独运行：可以完全没有 omp-echo-memory 目录
node .\omp-qq-bridge\launch.mjs

# OMP Echo Memory + QQ，沿用记忆启动器的模型配置与主会话目录
node .\omp-echo-memory\launch.mjs -e .\omp-qq-bridge\index.mjs

# 也支持反向组合，使用 QQ 启动器的模型配置与主会话目录
node .\omp-qq-bridge\launch.mjs -e .\omp-echo-memory\index.mjs
```

`-e` 只接受当前项目内真实存在的普通 JS/TS 文件；拒绝链接、目录、重复或项目外扩展。需要其他 QQ 桥接时，可不安装本目录，直接使用记忆启动器 `-e` 加载那个桥接的实际项目内入口。模型与主会话配置属于所选启动器，不因组合而自动搬移凭据；已有组合希望沿用记忆侧主会话目录时，使用上面的记忆启动器命令。

QQ 通过原生事件总线的 `project-memory:resolve` **公共协议 v1** 发现当前项目提供者；工具名、JSON Schema、人格与召回来自提供者，不硬编码 OMP Echo Memory 的工具、文件夹或存储格式。OMP Echo Memory 的提供者 ID 为 `omp-echo-memory`，功能工具名仍是 `echo_memory`、`echo_persona`。没有提供者时不注入额外人格/长期记忆，也不注册记忆工具；同时加载一个兼容提供者即可自动接入，不能有多个竞争者。提供者报错、身份不匹配或工具与 QQ 回复门槛/电脑读取工具冲突时明确失败，不静默回退成无记忆执行。

完整字段、取消/确认责任与第三方桥接接法见 [公共提供者协议](https://github.com/gulanthys/omp-echo-memory#公共提供者协议-v1)。同一 omp 会话可沿用已经加载的记忆工具和人格；另起子进程/私有会话的桥接必须显式实现该协议及受控工具转发，不能宣称任意第三方桥接都能零修改共享。提供者和原生扩展属于可信本机代码，协议不是 OS 沙箱。

`prepare(prompt, context?)` 的第二个可选参数传递本机可信来源；协议版本仍为 1，旧的单参数提供者可以忽略它。QQ 上下文为 `{ channel: 'qq', selfId, chat: { type: 'private' | 'group', id }, messages: [{ messageId, senderId }] }`，ID 为字符串，未知发送者为 `null`；不能从 `prompt` 自行恢复可信身份。第三方桥接须独立建立同等可信边界，否则只能视为未知来源。

## 自动接收的范围

- 所有后端上报的好友私聊、陌生/临时私聊，以及当前账号所在群的消息；不再按联系人名单或是否 @ 过滤接收。
- 新 QQ、新群自动创建独立上下文；同一个消息 ID 在不同聊天之间不会互相去重。
- 临时私聊按发送者 QQ 建上下文，保留来源群信息用于回复，不会误建成“与群号私聊”。
- 群里无关的消息也会交给模型，因此可能增加费用。**接收不等于发言**：由 AI 结合近期群聊、实际公开回复和项目人格/记忆，通过 `qq_reply_gate` 选择回复、表情回应或静默。@、引用、核心身份均不强制放行，也不授予后续连续回复资格。
- 好友/入群申请和其他通知在本机提示，不自动批准申请、加好友、入群或执行账号管理操作。

“所有信息”是**后端实时上报且当前账号有权收到的信息**，不代表读取其他人的私聊、导入过去所有聊天记录或补齐断线期间的全部历史。正向 WebSocket 没有可靠离线重放保证；本插件不再轮询最近 30 条历史，也不查询好友/群名单来猜测新聊天。

### 群聊语义参与与短期心情

`qq_reply_gate` 使用 `action: "reply" | "react" | "silent"`、`addressedToBot` 和 `reason`；可附加 `targetMessageId`、`quote`、`emojiId`、`mood`。旧布尔 `reply` 参数已移除。`addressedToBot` 是 AI 的语义判断记录，不是程序根据 @、关键词或发送者身份计算的开关。兴趣来自当前人格和经批准的记忆，但有兴趣不等于必须插话；AI 判断有具体补充价值时可以参与，别人转向互聊时重新旁听，没有 @ 的自然承接也可回应。

判断称呼时区分自己的名字、平台昵称与用户称呼：人格 `name/identity` 和本机批准信息描述自己；可信来源中的 `selfId`、`selfNickname` 分别来自已认证 QQ 账号及 `get_login_info` 返回的显示名，断线或换账号时清除旧昵称。昵称仅辅助语义辨认，不作为指令、改名或权限授权。供养者关系及对他的称呼不是机器人的名字。AI 需结合前后文理解新称呼是否指向自己，不能把上一轮对话、熟人或可回答的问题当作自动接话资格；不设固定姓名匹配、关键词拦截或群聊自动改名。

程序只校验并执行当前模型回合的决定：回复/表情的目标必须是本账号、本群已观察到的真实入站消息；无决定、非法目标、失败或取消的回合不会发言。绑定目标不等于显示引用：仅 `quote: true` 时在首段添加 QQ 引用块，否则直接说话；AI 按语境选择，简单承接通常不引用，话题交错或回较早消息时才考虑引用，不用人数、条数阈值或自动 @ 替代判断。表情使用 SnowLuma 的 [`set_msg_emoji_like`](https://snowluma.github.io/zh/docs/api/extended/set_msg_emoji_like)，失败或后端不支持时记录失败，不用另一条文字代替、不自动重试。私聊行为不变；表情回应仅用于群聊。

每个机器人账号/群的收件箱保存独立 `groupConversation`：近期历史、最新语义判断/执行结果和短期心情。历史最多保留 80 条、总计 24000 个文字字符，单条截断到 4000 字符；当前批次被历史预算挤出的消息仍单独交给模型。只把服务端确认发送并返回消息 ID 的机器人内容计入公开历史，静默草稿、失败输出和仅表情回应不会伪装成公开说过的话。短期心情可以随 `silent` 更新，不单独发成心情文字，也不自动写入人格、核心身份或长期记忆。

消息文字、旧判断和心情通过低信任 `groupContext` 提供给模型；系统身份块只含本机确认的来源元数据。新群消息到达时，尚未发布的旧决定会留待下一轮 AI 结合新上下文重新判断，不自动补发旧草稿；忙碌群可能因此更常旁听。这里没有新增冷却时间、固定关键词路由或“被 @ 必回”规则，语义仍可能误判，需要实测而非保证像人一样准确。

旧收件箱缺少这些字段时仍可读取，不为了初始化状态而改写；首次实际处理新群输入后才保存新增状态。表情可用 [`get_msg_emoji_likes`](https://snowluma.github.io/zh/docs/api/extended/get_msg_emoji_likes) 查询核对，API 成功不等于已人工确认客户端显示。

## 设置与权限

```text
/omp-qq-bridge /setting
```

只有五项：启用/停止、QQ 连接、共享角色与记忆说明、运行状态、可选语音转写。没有聊天名单、手工会话 ID、每聊人设或管理端口。

全量接收**不等于把电脑权限交给所有 QQ 联系人**：

- QQ 子会话仅提供 `read`、`grep`、`glob` 和本桥接工具；每次电脑数据读取仍需本机原生确认。确认框显示来源聊天及具体参数，结果可能进入模型并随回复发回该聊天。拒绝或取消时不会执行该次读取。
- 保存、强化、纠正、整理、遗忘记忆以及提交成长提案，均须本机确认。QQ 中回复“同意”不能代替本机审批。
- 安全扩展加载/执行失败时拒绝继续接收 QQ 工作，不在缺失确认机制时退回普通工具执行。
- 切换项目、结束回合、断开连接或停止桥接会使未提交确认失效。设置只在本项目主会话可用。

这不是 Windows 权限沙箱。经你明确批准的工具仍使用当前用户权限；同权限程序、omp 认证组件、发行版缓存和供应商日志不属于本插件的隔离保证。全量接收扩大了接触面，不要存入可向所有聊天透露的敏感长期记忆。

## 一个角色，多份短期上下文

加载记忆提供者时，人格和授权长期记忆由该提供者统一提供，本桥接不再建一套人设或记忆。使用 OMP Echo Memory 时来源是其 `persona.json` 和已批准成长；QQ 单独运行时沿用 omp/模型本身，不额外创建替代人格或本地长期记忆库。

每个 QQ 账号下的私聊、群聊分别保存短期上下文，例如 `contexts/<机器人QQ>/private-12345/`、`contexts/<机器人QQ>/group-54321/`。不会自动把私聊原文插入群聊；切换机器人账号也不会混用另一账号的原始聊天上下文或待处理队列。空闲子进程会释放，聊天历史留在项目内，下次继续使用。

长期记忆一旦批准保存，可能被本项目**任何接入聊天**召回。记忆写入的本机确认由提供者负责；本桥接提供绑定真实聊天和有效回合的本机确认回调，不以 QQ 文本替代审批。OMP Echo Memory 的检索不强化记忆，衰减、强化、纠正、遗忘及成长审批继续由 OMP Echo Memory 自己处理，批准/拒绝/撤销仍使用它的本机管理入口。

不自动将整段 QQ 聊天写成长期记忆。普通会话记录、待处理收件箱和长期记忆是不同数据；遗忘一条长期记忆不等于删除所有原始会话记录或供应商日志。

### 核心身份与可信 QQ 来源

使用 OMP Echo Memory 时，独立核心身份由其本机入口 `/omp-echo-memory core`、`/omp-echo-memory core-set <JSON>`、`/omp-echo-memory core-clear` 或不启动模型的 CLI 管理，详见 [记忆插件本机管理文档](https://github.com/gulanthys/omp-echo-memory)。桥接不另存一套角色配置、不硬编码操作者 QQ，也不提供 QQ 核心修改工具；本机确认普通记忆写入并不能授权核心身份修改。核心关系和称呼不授予任何 QQ 用户电脑读取、审批或本机管理权限。

身份仅取自当前真实 OneBot 消息信封：优先使用顶层 `user_id`，只有该字段缺失时才回退到 `sender.user_id`；非有效正整数或超出安全整数范围的发送者一律未知，非法顶层 ID 不通过回退升级成主人。显示昵称、群名片、正文伪造的 `[QQ ...]` 标头、引用和合并转发里的作者信息都不是当前发送者身份。此边界信任本机 OneBot 后端和扩展代码，不是对恶意后端或同权限进程的隔离。

私聊、群聊和临时私聊均按当前批次顺序保留每条真实消息 ID 与发送者 ID；混合群批次中主人的身份只属于对应消息，不扩散给其他成员。持久收件箱恢复仍从原信封重建来源，不从已渲染正文推断。来源经显式参数绑定到实际接收的模型回合，并通过本机回合票据约束回调；旧回合、其他聊天和重连前的来源不能替换新回合来源，回调正文自带的 `context` 不被采用。

每轮系统策略在普通人格、成长和提供者核心策略之后追加独立的可信 QQ 来源块，同时以 `prepare(prompt, context)` 交给提供者判断核心身份；不把身份元数据拼入不可信聊天正文。人格中的核心身份优先级由提供者明确规定，不依赖普通记忆召回或衰减。没有提供者时仍提供来源边界说明，但不建立核心角色库。此机制不改写输出、不保证模型永不误称；核心配置可能发送给所有接入聊天使用的模型，隐私与实际行为边界见 OMP Echo Memory 说明。

## 持久化、断线与自身回声

消息在进入模型前先写入本项目的分账号/聊天收件箱。模型忙时仍可继续接收和排队；投递前失败会保留输入并退避重试。只有实际写入子会话后才消费待处理消息；之后失败、超时、取消不自动重放，以免重复执行副作用。这不是跨网络的严格 exactly-once 保证，去重记录也是有界的。

连接先通过 `get_login_info` 确认机器人身份，随后每个事件的 `self_id` 必须匹配。机器人自身发送者、`message_sent` 及本聊天出站 ID 在媒体解析前过滤，避免自己跟自己聊。身份缺失、账号变化或断线时暂停旧回合；重新连接后按正确账号恢复尚未投递的输入。

回答绑定**开始处理时**的账号和连接代际，不会在重连后把旧回答当作新回答发送。每个出站段落前重新检查状态；关闭后不会继续发送后续段落，失败或结果未知的发送不自动重试。已经被 OneBot 接收的在途消息无法撤回。

存储失败会暂停接收，不能静默丢弃后继续运行。异常退出留下 `runtime.lock` 时，先确认旧进程退出，再手动删除锁；不自动抢锁。

## 图片、文件和语音

图片字节真实进入支持视觉的模型；支持卡片、合并/嵌套转发、原生图片和 Markdown 图片出站。媒体按账号/聊天分目录保存，不会因其他聊天使用相同消息 ID 而覆盖。未支持的文件/其他消息段以受限元数据说明，视频明确标为未解析，不假装已读取内容。

语音默认不执行外部程序。设置中可提供可信前台转写命令，用 `"{file}"` 表示音频参数；留空关闭。需自行准备 ASR 环境，不自动安装 Python、模型或依赖。所有接入语音都可能触发该命令；命令拥有当前用户权限，凭据请放环境变量，不写入命令。停止时取消下载及前台命令进程树，不管理你主动启动的独立后台服务。

## 数据与升级

这是测试预发布版，不提供自动更新器、全局安装或跨项目数据迁移。升级前停止桥接和相关 omp 进程，私下备份本项目 `.runtime/`，再在原目录更新到选定标签；不要覆盖、公开提交或复制其他项目的运行数据。旧版本回退前也应先备份，不能假设旧版理解新增群聊状态。单独升级记忆插件时遵循其自己的升级说明；本桥接不会迁移它的绑定、人格或长期记忆。

```text
omp-qq-bridge/.runtime/
  settings.json                         # v4 连接设置，可能含 OneBot Token
  inbox/<机器人QQ>/<聊天编码>.json       # 待处理输入、去重/出站 ID、短期群历史与心情
  inbox/<机器人QQ>/<聊天编码>-media/     # 本聊天图片、音频
  contexts/<机器人QQ>/private-<QQ>/      # 本聊天模型引导配置及会话历史
  contexts/<机器人QQ>/group-<群号>/
  runtime.lock
```

长期记忆由所选提供者保存在它自己的项目内目录，本桥接不复制到各聊天目录。内部 HTTP 只服务经过聊天 token 和当前回合验证的策略、已声明工具及本机授权回调，不提供管理网页或公开设置 API。独立运行时不会调用记忆提供者，也不会注册记忆工具，但电脑读取确认仍然有效。

实际业务配置仅保留 `enabled`、`onebotUrl`、`token`、`speechCommand`；`version`、`projectRoot` 用于版本及项目归属校验。`revision` 与旧 `echoMemoryDir` 均已废弃，原 v4 文件可继续读取，读取和启动不改写文件，下次保存才移除这两个已知遗留字段。旧记忆目录字段不再决定接入对象，只有本次显式加载、通过项目校验的提供者才能被发现；其他未知字段仍拒绝。

图片接收/发送、回复分段和 QQ 标记剥离采用固定行为，不再保留无入口的开关。图片数量预算为 4、大小预算为 5 MiB，外部转写超时为 60 秒，均保留原默认值并改为代码常量；图片路径仍受项目根目录边界检查。语音转写仅由命令是否填写控制，不另设重复启用标志。消息合批参数仍用于内部调度，不增加用户设置项。

**v3 必须重新运行 `/init`。** 不会沿用旧版 enabled 状态而悄悄扩大到所有聊天；旧名单不再生效，也不会自动删除旧聊天数据。新模式使用按机器人账号隔离的目录，不自动搬用旧版无账号命名空间的上下文。更早的 `.omp-qq/` 同样不再读取，仍保留忽略规则，避免误提交旧凭据。

连接 Token 保存在项目内；运行时按 OneBot 标准通过查询参数鉴权，不把 Token 拼进保存的服务器地址或公开诊断。服务端/代理可能记录连接 URL，跨机器部署应使用可信网络、TLS 和妥善的服务端日志策略。`.gitignore` 不是加密或备份删除机制。

## 维护规范

- JavaScript 和可选 Python 转写脚本的函数、变量及内部字段使用英文标识符；中文用于界面提示、内容文本和必要注释。OneBot 字段、工具名及现有转写 CLI 参数保持原接口。
- 运行时直接使用英文选项，不再将设置转换成中文键。本插件保存的旧 v4 配置不需要重新初始化，读取时只忽略已废弃的 `revision`、`echoMemoryDir`。更早删除的中文选项仅属于原运行时适配层，不是持久化字段；其他未知字段仍会被拒绝。
- ESLint 检查 JavaScript 标识符、未使用变量、控制流花括号和常见错误；Prettier 统一 JavaScript、JSON 与 Markdown 排版。两者只配置在本目录，不修改其他项目或全局工具设置。
- 预期的清理失败、队列恢复和默认拒绝授权均有意图注释；不要用空 catch 掩盖业务失败，也不要为了恢复队列而重放结果未知的发送。

```powershell
npm --prefix .\omp-qq-bridge run lint
npm --prefix .\omp-qq-bridge run format:check
npm --prefix .\omp-qq-bridge run format
```

`format` 会修改匹配文件，`lint` 和 `format:check` 不修改源码；运行数据、依赖目录和 npm 锁文件不参与格式化。Python 转写脚本不属于 ESLint/Prettier 的检查范围，也不是桥接普通运行的依赖。

## 验证与协议来源

普通运行没有 npm 运行依赖，`npm ci` 仅用于开发检查；其中 `ws` 仅供测试服务端使用。开发依赖固定引用公开 Release `omp-echo-memory v1.1.0-beta.1` 的 HTTPS 运行包，锁文件保存下载地址与完整性校验，安装测试依赖不需要 GitHub SSH 凭据，也无须克隆同级记忆仓库。测试通过公共 `omp-echo-memory/api` 导出调用真实提供者，用 `import.meta.resolve` 定位已安装包并复制发布源码、通用人格模板到隔离临时项目，再创建新的测试绑定；不会复制开发者的本地人格、绑定或 `.runtime/`。独立、替代后端及两个真实记忆组合烟测仍分别运行，替代后端不代替真实记忆集成覆盖。`check` 依次运行 ESLint、Prettier 检查及完整回归：

```powershell
npm --prefix .\omp-qq-bridge ci
npm --prefix .\omp-qq-bridge run check
npm --prefix .\omp-qq-bridge run smoke
```

源码仓库包含开发测试；运行包的 `files` 白名单仅发布运行代码、可选转写脚本、README、变更记录与许可证，不含 `.runtime/`、测试夹具或本机凭据。本测试版通过 GitHub 分发，不发布 npm。

本测试版从公开记忆 Release 的 HTTPS 包实际安装开发依赖并生成锁文件后，真实 omp 18.18.0 四组合烟测通过：记忆启动器组合、QQ 启动器反向组合、没有记忆目录的 QQ 单独运行、QQ 加独立替代记忆后端。替代后端使用自己的存储和不同工具名，验证动态 JSON Schema、共享召回以及允许/拒绝写入。每种模式均覆盖原生命令、自动接入新私聊/新群、全部群成员输入、电脑读取确认与拒绝、上下文隔离、重启去重、断线重连、大图、自身回声和停止；无提供者模式不执行记忆场景。

83 项回归通过，ESLint 与 Prettier 检查通过。覆盖可信发送者与伪造来源、混合批次及恢复、回合票据及重连隔离、提供者兼容，以及群回复/表情/静默的执行边界、真实目标绑定、可选引用、短期历史预算、失效决定抑制、昵称跨账号清除。模型判断在回归里由模拟器提供；这些结果证明执行约束，不证明 AI 理解真实群聊。兼容回归验证旧 v4 文件的读取/关闭不改写及保存清理；未知设置仍拒绝。转写进程、QQ 标记剥离和按段回复的验证不代表真实 ASR 识别验收。

本节自动化烟测的 QQ 与模型端点使用本机协议模拟器，不等于真实 QQ 收发或语音验收。核心身份另有真实 GPT-6 Luna 配合受控发送者元数据的既有三场景验证，见 [OMP Echo Memory 验证说明](https://github.com/gulanthys/omp-echo-memory#验证与-beta-限制)；不是对模型永不误称的保证。macOS 运行上述检查时设置 `TMPDIR=/private/tmp`，避免默认临时目录别名触发项目路径隔离检查。

群聊语义验收须审阅真实的前后发言、当轮判断与实际公开输出，不能用固定消息顺序、是否 @ 或预设动作代替人工判断。真实群自然观察已发现并处理“每条强制引用”和“把陌生称呼直接认作自己”的问题；非引用回复、无 @ 承接、收到无指向图片后静默并记录短期心情有实际记录。称呼修正后另用真实 GPT-6 Luna 重读两段原对话：转向另一人询问出发安排时选择静默，承接游戏的无 @ 问句仍自然回复；独立诊断能区分人格名与 QQ 显示昵称。这次重放使用隔离的模拟 OneBot，不是再次发送到 QQ 群，也不是自动语义评分。模型仍可能误判；真实表情的客户端显示与多人长期稳定性尚未完成验收，不据此宣称所有场景通过。
